# Langfuse - LLMOps, Tracing & Evaluation

An open-source LLM observability platform: full traceability of prompt calls, latency,
metadata, tokens, and cost.

---

## Files

Langfuse has **no configuration file** mounted into its containers (`langfuse-web`,
`langfuse-worker`) — its entire configuration comes from environment variables defined directly
in [`../docker-compose.yml`](../docker-compose.yml) and hydrated into `.env` by `./init.sh`.
This folder therefore only contains this documentation.

---

## Key Variables (`.env`)

| Variable | Role |
| :--- | :--- |
| `LANGFUSE_SALT` / `LANGFUSE_ENCRYPTION_KEY` / `LANGFUSE_NEXTAUTH_SECRET` | Cryptographic secrets, randomly generated by `./init.sh` (never hardcoded). |
| `LANGFUSE_INIT_ORG_ID` / `LANGFUSE_INIT_ORG_NAME` (`LLMStack`) | The default organization, created only on the **first startup** (the variable is ignored afterward). |
| `LANGFUSE_INIT_PROJECT_ID` / `LANGFUSE_INIT_PROJECT_NAME` (`llm-stack-project`) | The default project, created on first startup. |
| `LANGFUSE_INIT_PROJECT_PUBLIC_KEY` / `LANGFUSE_INIT_PROJECT_SECRET_KEY` | The project's API keys — **must stay in sync** with [`../litellm/litellm.env`](../litellm/litellm.env) (docker-compose does not interpolate `${VAR}` inside an `env_file`, so `./init.sh` duplicates the literal values). |
| `LANGFUSE_INIT_USER_EMAIL` / `LANGFUSE_INIT_USER_NAME` / `LANGFUSE_INIT_USER_PASSWORD` | Declarative admin user bootstrap, seeded via Vault (`UI_PASSWORD`). |
| `LANGFUSE_S3_*` | Storage for media, events, and batch exports on SeaweedFS (the internal S3 backend). |

## Declarative Bootstrap & Organization/Project Membership

Langfuse natively supports headless bootstrapping of organizations, projects, and users via environment variables:
- `LANGFUSE_INIT_ORG_ID` and `LANGFUSE_INIT_ORG_NAME` create the default organization on startup.
- `LANGFUSE_INIT_PROJECT_ID` and `LANGFUSE_INIT_PROJECT_NAME` create the default project and API keys.
- `LANGFUSE_INIT_USER_EMAIL`, `LANGFUSE_INIT_USER_NAME`, and `LANGFUSE_INIT_USER_PASSWORD` bootstrap the admin user and automatically assign `OWNER` membership to both the organization and project.

When the admin logs in via Authentik SSO, NextAuth links the OIDC account to the pre-provisioned user (`AUTH_CUSTOM_ALLOW_ACCOUNT_LINKING: "true"`), granting immediate owner access without requiring manual onboarding or procedural SQL mutations.

## Distributed Storage

| Component | Role |
| :--- | :--- |
| PostgreSQL | Metadata (organizations, projects, users, memberships). |
| ClickHouse | Analytics logs (traces, observations, scores) — dedicated `langfuse_clickhouse_data`/`langfuse_clickhouse_logs` volumes. |
| SeaweedFS (S3) | Uploaded media, event exports, batch exports. |
| Redis | Asynchronous task queues (`langfuse-worker`). |

## UAT Ingestion Proof

The `LANGFUSE` smoke test performs an additional, UAT-only ingestion round trip when
run through `make uat-smoke-test`. It submits one uniquely identified synthetic
`trace-create` event to Langfuse's current `dual`-mode ingestion API, requires a
per-event success response, reads the exact event object from SeaweedFS using
SigV4 and verified internal TLS, and waits for the matching ClickHouse trace.
Only the synthetic event body is inspected; credentials and object contents are
never printed. The UAT application volume is disposable, so no production data
is created or removed by this check.

The ordinary production smoke test retains its read-only Langfuse checks. An
operator can explicitly opt into the same synthetic ingestion round trip in
production with:

```bash
SMOKE_ENVIRONMENT=production SMOKE_PROD_LANGFUSE_INGESTION=1 ./smoke_test.sh LANGFUSE
```

This creates one uniquely named synthetic production trace; it does not delete
or alter existing traces. The probe verifies both public system trust and the
internal Traefik CA when `TLS_MODE=internal`, without disabling certificate or
hostname verification. It checks the configured legacy ingestion path, not
historical event recovery. Migrating LiteLLM to Langfuse's OTel callback
requires a separate CAB and regression test.

### Optional continuous ingestion alert

On a systemd host, `./setup.sh` also generates two user-unit files in
`systemd/`. After the stack is healthy, enable the timer with
`make langfuse-monitor-enable`; stop it with `make langfuse-monitor-disable`.
The timer runs every five minutes and invokes only the production ingestion
round trip, not the full SSO smoke test. The one-shot process atomically writes
only a success bit and completion timestamp into `prometheus/textfile/`.
Node Exporter's textfile collector exposes them to Prometheus. Critical rules
fire on failure or if the last run is over 15 minutes old and are delivered to
the receivers configured in Alertmanager. No event data,
object keys, credentials, or exception text enter metrics or alerts. Every run
creates exactly one synthetic trace, so operators should account for
approximately 288 per day.
The user systemd manager must remain active across logout (`loginctl enable-linger`).
On non-systemd hosts,
the one-shot command remains available and the timer is not installed.

Enabling the timer recreates only `node-exporter` to activate its read-only
textfile collector, then runs one successful probe before enabling the timer.
It also reloads Prometheus rules after the first metric is available.
Check `systemctl --user status llm-stack-langfuse-ingestion.timer` and
`journalctl --user -u llm-stack-langfuse-ingestion.service --since=1h` after
enabling it. Disable the timer before rolling back the monitor code; disabling
also removes only its generated metric file. A failed probe produces a zero
metric and nonzero service exit. A stopped timer produces a stale timestamp,
while a down Node Exporter is covered by the existing `ServiceDown` alert.
This monitor does not recover historical events.

S3 batch exports: `LANGFUSE_S3_BATCH_EXPORT_EXTERNAL_ENDPOINT=https://s3.${DOMAIN}` — the
generated download links (signed with SigV4) point to SeaweedFS's real S3 API, routed by Traefik
**without** going through Authentik (a valid SigV4 signature is itself a security guarantee, and
is incompatible with requiring a Forward-Auth session cookie).

## Scoped Metadata Snapshot (Pre-production Tool)

`../scripts/langfuse_snapshot.py` creates an encrypted, PostgreSQL-only logical
snapshot of the `langfuse` database. The archive is streamed directly from
`pg_dump -Fc` into GnuPG AES-256; no unencrypted dump is written on the host.
The working directory must already exist outside any Git worktree, be owned by
the caller, and have mode `0700`. Archive and manifest files use mode `0600`.
The passphrase is entered on a terminal or supplied through an inherited file
descriptor, never as a command-line argument or a new `.env` variable.

```sh
install -d -m 700 /absolute/protected/work-directory
python3 scripts/langfuse_snapshot.py snapshot \
  --project-dir /absolute/path/to/production/llm-stack \
  --output-dir /absolute/protected/work-directory
python3 scripts/langfuse_snapshot.py verify \
  --archive /absolute/protected/work-directory/langfuse-EXACT-NAME.pgdump.gpg
python3 scripts/langfuse_snapshot.py rollback \
  --project-dir /absolute/path/to/production/llm-stack \
  --archive /absolute/protected/work-directory/langfuse-EXACT-NAME.pgdump.gpg \
  --confirm langfuse-EXACT-NAME.pgdump.gpg
```

`snapshot` runs the same isolated restore before reporting success. `verify`
can repeat it later: it checks the manifest and SHA-256, decrypts in a pipe,
and restores into an isolated, network-disabled PostgreSQL 18.6 container
whose data and socket are in tmpfs. It reports only row counts for users,
organizations, and projects.
`snapshot` also compares those counts with a read-only source query and fails
closed if they differ; concurrent metadata writes can therefore require a retry.

`rollback` safely reinjects the snapshot into the target PostgreSQL database:
1. Runs isolated `verify` in tmpfs PostgreSQL as a mandatory preflight validation.
2. Enforces `--confirm <archive-basename>` to prevent accidental restoration.
3. Temporarily stops `langfuse-web` and `langfuse-worker` writers (`litellm`, `authentik-server`, and `postgres` remain active).
4. Terminates active backend connections to `langfuse` and streams `pg_restore --clean --if-exists --single-transaction`.
5. Guarantees restarting consumers in `finally` and validates post-rollback live row counts.

The archive covers Langfuse **PostgreSQL metadata only**. It does not contain
ClickHouse traces, SeaweedFS objects, Redis queues, or any other application's
database. Do not use it as a whole-stack disaster recovery backup.

`https://langfuse.${DOMAIN}` — native OIDC ("Login with SSO" button), using the same Authentik
