# LiteLLM - Gateway / LLM Router

This folder holds the LiteLLM proxy configuration: model declarations, guardrails, and
observability callbacks (Langfuse, Prometheus).

---

## Files

| File | Role | Tracked in Git |
| :--- | :--- | :--- |
| [`litellm-config.yaml`](litellm-config.yaml) | Declares models, guardrails, and callbacks. Mounted into the container at `/config.yaml`. | Yes (no secrets) |
| `litellm.env` | Langfuse API keys (`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`), loaded via docker-compose's `env_file`. | No, gitignored, regenerated by `./init.sh` |

---

## Declared Models

Every model is an alias of the **same single weight**, bundled inside this Docker Compose
project — `lfm2-1.2b-rag`, running on the `ollama` service (`http://ollama:11434`,
CPU-only, no GPU, no external machine). This stack used to depend on `llama-server`, a GPU
backend on a separate physical machine; that dependency has been fully removed — see
[`../ollama/README.md`](../ollama/README.md) for the full rationale and details.

| Model name (LiteLLM alias) | Purpose |
| :--- | :--- |
| `lfm2-1.2b-rag` | General/default RAG-optimized model (also Open WebUI's `DEFAULT_MODELS`). |

## PII Guardrail (Presidio-compatible)

The upstream Microsoft Presidio containers are not deployed. Instead, LiteLLM's built-in `presidio` guardrail (`presidio-pii-masking` in [`litellm-config.yaml`](litellm-config.yaml)) points at [Betterleaks](../betterleaks/README.md), which exposes Presidio-compatible `/analyze` and `/anonymize` endpoints. The guardrail runs `pre_call` on the input only, so streamed (SSE) responses are not buffered.

## SSO Admin Role (`proxy_admin`)

`UI_ADMIN_USERS` and `PROXY_ADMIN_AT_LOG_IN` (environment variables on the `litellm` service in
[`docker-compose.yml`](../docker-compose.yml)) only apply when a user row is **first created**
in `LiteLLM_UserTable` — never retroactively on an account that already exists with a lower role
(for example, `internal_user_viewer`).

Without the `proxy_admin` role, the **Settings** and **Guardrails** tabs in the LiteLLM UI stay
hidden, even for an SSO account that belongs to Authentik's `admins` group.

`init.sh` (step 9) fixes this: it triggers a first SSO login for `admin@example.com` (to make
sure the user row exists), then runs a direct SQL `UPDATE` on `LiteLLM_UserTable` to force
`user_role = 'proxy_admin'`. This step is idempotent and has no effect on an account that is
already an admin.

## Master Key

`general_settings.master_key: os.environ/LITELLM_MASTER_KEY` — never hardcoded, always resolved
from the `LITELLM_MASTER_KEY` environment variable (randomly generated by `./init.sh`, unique per
deployment).

## Observability

* **Prometheus**: `require_auth_for_metrics_endpoint: false` allows internal scraping (Docker
  network only, never exposed publicly) — see [`../prometheus/README.md`](../prometheus/README.md).
* **Langfuse**: `success_callback: ["langfuse"]` — every completion call is traced (latency,
  tokens, cost) — see [`../langfuse/README.md`](../langfuse/README.md).

## Adding Custom & Private Models (`custom_models.yaml`)

LiteLLM supports native file includes (`include: ["custom_models.yaml"]`).

To add private, remote, or self-hosted models (e.g., a `llama-server` on a remote GPU machine, vLLM, or external API providers) without committing secrets or private endpoints to Git:

1. **Edit [`custom_models.yaml`](custom_models.yaml)**:
   ```yaml
   model_list:
     - model_name: unsloth/Qwen3.8-27B-GGUF:UD-Q6_K_XL
       litellm_params:
         model: openai/unsloth/Qwen3.8-27B-GGUF:UD-Q6_K_XL
         api_base: http://192.0.2.10:8080/v1
         api_key: "sk-no-key-required"
       model_info:
         supports_reasoning: true
   ```

2. **Tell Git to ignore your local changes**:
   ```bash
   git update-index --assume-unchanged litellm/custom_models.yaml
   ```
   *(To track changes again if needed: `git update-index --no-assume-unchanged litellm/custom_models.yaml`)*.
