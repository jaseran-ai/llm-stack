# Traefik v3 — Cloud-Native Reverse Proxy, Routing & Dynamic Ingress

A modern, declarative, edge reverse proxy integrated into `llm-stack`. Handles virtual subdomains, dynamic Docker provider route discovery, forward-authentication via Authentik, and SSL/TLS termination across multiple deployment scenarios.

---

## 🏗️ Architecture & Component Integration

| Component | Role | Configuration / Path |
| :--- | :--- | :--- |
| **`traefik`** | Core reverse proxy (`traefik:v3.6.1`). Listens on ports `80` (HTTP) and `443` (HTTPS). | [`traefik.yml`](traefik.yml), [`dynamic.yml`](dynamic.yml), [`docker-compose.yml`](../docker-compose.yml). |
| **Hydration Script** | Generates static and dynamic configs based on `TLS_MODE` and `DOMAIN`. | [`scripts/hydrate_traefik.py`](scripts/hydrate_traefik.py). |
| **Docker Provider** | Dynamic route discovery via container labels (`traefik.http.routers.*`). | Declared on each service in [`docker-compose.yml`](../docker-compose.yml). |
| **Authentik Forward-Auth** | Middleware protecting interactive and administrative endpoints. | Middleware `authentik-auth@file` pointing to `http://authentik-server:9000/outpost.goauthentik.io/auth/traefik`. |

## 🔑 Key Features & Subtleties

### 1. Dual Entrypoint Routing (Cloudflare Tunnel + Direct HTTPS)
* Traefik exposes two distinct entrypoints:
  * **`web` (`:80`)**: Accepts internal plaintext HTTP traffic forwarded by Cloudflare Tunnel (`cloudflared`) with `X-Forwarded-*` trusted headers.
  * **`websecure` (`:443`)**: Handles direct TLS connections with automated certificate management.
* Each container specifies dual routers (e.g. `chat` on `websecure` and `chat-http` on `web`) to ensure seamless traffic flow without endless redirect loops.

### 2. TLS Termination Modes (`TLS_MODE`)
Set in `.env`, or with `./setup.sh --tls-mode=MODE` (which also updates an existing `.env`):
* **`internal` (Default)**: Ingress certificate for `DOMAIN` and `*.DOMAIN` signed by the stack's local CA (`traefik/certs/internal-ca.crt`). Trust that CA on client machines to avoid browser warnings.
* **`custom`**: Ingress certificate signed by your own certificate authority (see below).
* **`http-01`**: Automatic Let's Encrypt certificates via ACME HTTP-01 challenge for standard publicly accessible servers.
* **`cloudflare-dns01`**: Automated DNS-01 challenge using Cloudflare API tokens for environments without inbound open ports.

### 3. Certificate Material (`traefik/certs/`, gitignored)
Generated by [`scripts/certs.sh`](scripts/certs.sh), called from `setup.sh`. Two independent trust chains:

| File | Purpose |
| :--- | :--- |
| `internal-ca.crt` / `.key` | Local CA, always generated (ECDSA P-256, 10 years). Trusted by Vault, Vault Agent and Traefik's `vault-transport`. |
| `vault.crt` / `.key` | Vault listener certificate (`vault`, `localhost`, `127.0.0.1`), signed by the local CA in every mode. |
| `tls.crt` / `.key` | Ingress certificate served by Traefik for `DOMAIN` and `*.DOMAIN` (`internal` and `custom` modes). |
| `ca.crt` | CA chain trusted by clients behind Traefik: Langfuse and CHouse UI (`NODE_EXTRA_CA_CERTS`) and Vault's OIDC discovery. Local CA in `internal` mode, your CA chain in `custom` mode. |
| `trust.crt` | `internal-ca.crt` + `ca.crt`, used by host-side provisioning scripts. |
| `custom.key` / `custom.csr` | Key and certificate signing request for your CA (`./setup.sh --tls-csr`). |
| `custom.crt` / `custom-ca.crt` | Your signed certificate chain and your CA chain, installed as `tls.crt` / `ca.crt` in `custom` mode. |

In `internal` mode the ingress certificate is reissued automatically when `DOMAIN` changes.

### 4. Using a Certificate From Your Own CA (`custom`)
1. Generate an ECDSA P-256 key and CSR for `DOMAIN` and `*.DOMAIN`. The certificate currently served is not touched, so this can be done while the stack runs:
   ```bash
   ./setup.sh --tls-csr
   ```
   Submit `traefik/certs/custom.csr` to your CA.
2. Once signed (serverAuth, SANs `DOMAIN` and `*.DOMAIN`), place:
   * `traefik/certs/custom.crt`: the signed certificate followed by any intermediate certificates;
   * `traefik/certs/custom-ca.crt`: your CA chain (intermediates and root).
3. Switch to the custom mode:
   ```bash
   ./setup.sh --tls-mode=custom
   ```
   The script checks that the certificate matches `custom.key`, covers both names, chains to `custom-ca.crt` and is not expired (warning under 30 days), installs it as `tls.crt` / `tls.key` / `ca.crt`, and persists `TLS_MODE=custom`. Then run `./start.sh` (restart `traefik`, `langfuse-web`, `chouse-ui` and `vault` if the stack is already running).

To renew, run `./setup.sh --tls-csr` again (new key; the installed certificate keeps being served), then repeat steps 2-3. Vault keeps its certificate from the local CA: an enterprise CA rarely signs `vault`, `localhost` or IP addresses, and these names never leave the host.
