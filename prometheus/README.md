# Prometheus - Metrics Collection

A time-series collection and storage server (TSDB) that monitors the health and performance of
the stack.

---

## Files

| File | Role | Tracked in Git |
| :--- | :--- | :--- |
| [`prometheus.yml.template`](prometheus.yml.template) | Source template, with a `${QDRANT_API_KEY}` placeholder. | Yes |
| `prometheus.yml` | The final file mounted into the container (`/etc/prometheus/prometheus.yml`), prepared by `./setup.sh` and hydrated by `./start.sh` after Vault Agent renders the Qdrant API key. | No, gitignored, regenerated on every run |
| `textfile/` | Optional machine-local Langfuse ingestion result and completion timestamp, read-only in Node Exporter. | No, gitignored, generated by `./setup.sh` |

---

## Scrape Jobs (`scrape_configs`)

| Job | Target | `metrics_path` | Auth |
| :--- | :--- | :--- | :--- |
| `litellm` | `litellm:4000` | `/metrics/` (trailing slash required) | None (internal network only) |
| `qdrant` | `qdrant:6333` | `/metrics` | `api-key: <QDRANT_API_KEY>` |
| `cadvisor` | `cadvisor:8080` | `/metrics` | None |

### Why `metrics_path: '/metrics/'` for LiteLLM?

LiteLLM redirects `GET /metrics` (without a trailing slash) to `/metrics/` with a `307 Temporary
Redirect`. Prometheus does **not** follow HTTP redirects when scraping — without the explicit
trailing slash in the config, the `litellm` job fails silently (shown as `down` on the `/targets`
page, but with no other visible symptom). This has been configured correctly from the start.

---

## Qdrant API Key

Qdrant requires an API key for every request, including `/metrics`. `./start.sh` invokes
`scripts/hydrate_config.sh` only after Vault Agent renders `qdrant.env` into RAM. The script
injects that runtime key into `prometheus.yml` and fails explicitly if it is unavailable; the
key is never hardcoded in the committed template.

## Access

* **Prometheus UI**: `http://127.0.0.1:9190` (restricted to `localhost`, never exposed through
  Traefik).
* **Checking targets**: `http://127.0.0.1:9190/targets` — every job should show `State: UP`.
  Automatically verified by `smoke_test.sh` (the "Prometheus Observability" test).

## Downstream Usage

The metrics collected here feed the Grafana dashboards
([`../grafana/dashboards/`](../grafana/dashboards)) and are automatically provisioned as a
Grafana data source at startup.

The optional systemd Langfuse ingestion monitor publishes only a success bit and
completion timestamp through Node Exporter's textfile collector. Critical
Prometheus rules alert on a failed round trip or a timestamp older than 15
minutes. The metric does not include secrets, object keys, or trace IDs. See
[`../langfuse/README.md`](../langfuse/README.md) for activation and rollback.
